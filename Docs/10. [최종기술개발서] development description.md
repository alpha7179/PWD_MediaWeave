# Media Weave 기술 개발서

---

## 1. 프로젝트 개요 (Project Overview)

### 1.1. 프로젝트명 및 소개

**Media Weave (미디어 위브)**  
*"우리의 이야기를 한곳에, 디미를 잇다"*

아주대학교 디지털미디어학과 재학생을 위한 **종합 학습 관리 플랫폼**으로, 5개 자율 트랙(GI, VC, CD, MD, DE)의 복잡한 커리큘럼을 시각화하고 개인 맞춤형 학습 계획 수립을 지원하는 웹 애플리케이션입니다.

### 1.2. 기획 의도 및 해결 문제

**핵심 문제 인식:**
- **정보 비대칭**: 5개 트랙, 100개 이상의 전공선택 과목으로 인한 학습 경로 설계 어려움
- **선수과목 복잡성**: 과목 간 의존 관계가 복잡하여 수강 계획 수립 시 실수 빈발
- **성과 파편화**: 학생 프로젝트가 개인 GitHub, Notion에 분산되어 체계적 아카이빙 부재
- **비효율적 팀 구성**: 역량 기반 팀원 매칭 시스템 부재로 인한 시간 소모

**솔루션 접근:**
- React Flow 기반 **인터랙티브 트랙 로드맵** 시각화
- 드래그앤드롭 기반 **4년 8학기 커리큘럼 플래너**
- **프로젝트 갤러리**를 통한 학습 성과 아카이빙
- **팀 빌딩 시스템**으로 역량 기반 협업 지원

### 1.3. 개발 환경 및 팀 구성

- **개발 기간**: 2024년 9월 ~ 2024년 12월 (4개월)
- **팀 구성**: 1인 개발 (Full-Stack)
- **개발 방법론**: Agile 기반 점진적 개발
- **버전 관리**: Git + GitHub (Private Repository)

- **운영 단순성**: 단일 데이터베이스로 백업, 모니터링 관리 용이

#### 3.3.2. 선수과목 검증 알고리즘

**도전 과제**: 복잡한 선수과목 의존성을 실시간으로 검증하여 사용자에게 경고 제공

```javascript
// curriculumStore.js - 선수과목 검증 로직
const validatePrerequisites = () => {
  const warnings = [];
  const completedCourses = getCompletedCourses();
  
  semesters.forEach((semester, semesterIndex) => {
    semester.courses.forEach(course => {
      const prerequisites = getPrerequisites(course.code);
      const missingPrereqs = prerequisites.filter(
        prereq => !completedCourses.has(prereq) && 
                  !isScheduledBefore(prereq, semesterIndex)
      );
      
      if (missingPrereqs.length > 0) {
        warnings.push({
          course: course.code,
          missing: missingPrereqs,
          semester: semesterIndex + 1
        });
      }
    });
  });
  
  return warnings;
};
```

**성과**: 실시간 선수과목 검증으로 수강 계획 오류 사전 방지

## 4. 개발 과정 중 변동 사항 (Changes & Refactoring)

### 4.1. 아키텍처 변경 사항

#### 4.1.1. 데이터베이스 아키텍처 단순화

**초기 계획**: PostgreSQL + MongoDB 하이브리드 구조
- PostgreSQL: 관계형 데이터 (사용자, 과목, 프로젝트)
- MongoDB: 문서형 데이터 (커리큘럼, 활동 로그)

**변경 후**: PostgreSQL 단일 데이터베이스
- **변경 사유**: 
  - 프로젝트 규모가 작아 NoSQL의 확장성 이점 불필요
  - 관계형 데이터가 대부분이어서 PostgreSQL이 더 적합
  - 인프라 복잡성 최소화 및 운영 비용 절감
- **기술적 해결**: PostgreSQL의 JSON 타입 활용으로 유연성 확보

#### 4.1.2. 실시간 통신 방식 변경

**초기 계획**: WebSocket 기반 실시간 채팅
**변경 후**: HTTP 폴링 기반 메시지 시스템
- **변경 사유**: 
  - 동시 접속자 수가 적어 WebSocket 오버헤드 불필요
  - 구현 복잡도 감소 및 디버깅 용이성
  - React Query의 자동 리페칭 기능 활용 가능

### 4.2. 기능 스펙 변경

#### 4.2.1. 스마트 스케줄러 기능 축소

**초기 계획**: AI 기반 최적 수강 계획 추천
**변경 후**: 기본 구조만 구현, 향후 확장 예정
- **변경 사유**: 
  - 머신러닝 모델 개발에 필요한 충분한 데이터 부족
  - 개발 일정 내 완성도 높은 구현 어려움
- **대안**: 선수과목 검증 및 졸업요건 체크 기능으로 대체

#### 4.2.2. 파일 저장 방식 변경

**초기 계획**: AWS S3 클라우드 스토리지
**변경 후**: 로컬 파일 시스템 + 향후 S3 마이그레이션
- **변경 사유**: 
  - 개발 단계에서 AWS 비용 최소화
  - 로컬 개발 환경에서의 빠른 테스트 가능
- **마이그레이션 준비**: Multer 설정으로 S3 전환 용이하게 설계

### 4.3. UI/UX 개선 사항

#### 4.3.1. 트랙 로드맵 레이아웃 최적화

**초기 구현**: 단순 그리드 배치
