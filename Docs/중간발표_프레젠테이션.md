## 🎯 Slide 2: 해결하고자 하는 문제

### 1. 높은 자율성에 따른 정보 비대칭
- 5개 트랙, 100개 이상의 전공선택 과목
- 선수과목 관계 복잡
- **→ 학생들의 진로 설계 어려움**

### 2. 교과목 정보의 불투명성
- 학과요람 PDF만 제공
- 실제 난이도, 기술 스택, 결과물 수준 파악 어려움
- **→ 기대와 다른 과목 선택**

### 3. 학습 성과의 파편화
- 프로젝트가 개인 GitHub, Notion에 분산
- 체계적 아카이빙 부재
- **→ 선배 성과 참고 불가**

### 4. 비효율적인 팀 구성
- 에브리타임 등 비공식 채널 의존
- 역량 기반 매칭 부재
- **→ 팀 구성 시간 소모, 프로젝트 질 저하**

## 💻 Slide 8: 구현된 핵심 기술

### 1. React Flow 기반 로드맵 시각화
```javascript
// 동적 레이아웃 알고리즘

2. 학기별 최대 행 수 계산 (1학기/2학기)
3. 트랙별 X 좌표 오프셋 (5개 트랙)
4. 선수과목 관계 기반 엣지 생성
5. 학년 박스 높이 자동 계산
```

**성능 최적화:**
- 100개 이상 노드 렌더링
- 메모이제이션 (useMemo)
- 가상 스크롤링

### 2. CSV 데이터 파싱 및 캐싱
```javascript
// PapaParse + Promise.all
const loadCurriculumData = async () => {
  const [courses, prerequisites, tracks] = 
    await Promise.all([
      parseCsv('Course.csv'),          // 100+ 과목
      parseCsv('Course_Prerequisites.csv'), // 200+ 관계
      parseCsv('Track.csv')            // 5개 트랙
    ]);
  
  // 메모리 캐싱으로 재로딩 방지
  return { courses, prerequisites, tracks };
};
```

### 3. 드래그 앤 드롭 (@dnd-kit)

## 🔒 Slide 16: 보안 및 개인정보 보호

### 인증 및 권한
- **JWT 기반 인증**: Stateless, 확장 가능
- **Role-Based Access Control**: Student, Professor, Admin
- **Refresh Token**: Access Token 탈취 시 피해 최소화

### 데이터 보안
- **비밀번호 암호화**: Bcrypt (Salt Rounds: 10)
- **HTTPS 통신**: AWS Certificate Manager
- **SQL Injection 방지**: ORM 사용 (Parameterized Query)
- **XSS 방지**: React 기본 이스케이핑 + DOMPurify

### 개인정보 보호
- **최소 수집**: 이름, 학번, 이메일만 수집
- **공개 범위 설정**: 커리큘럼, 프로젝트 공개/비공개 선택
- **데이터 삭제**: 회원 탈퇴 시 즉시 삭제

## 💬 Q&A

### 예상 질문

**Q1: 왜 PostgreSQL과 MongoDB를 함께 사용하나요?**
- A: 과목, 사용자 등 관계형 데이터는 PostgreSQL, 유연한 스키마가 필요한 커리큘럼 플랜은 MongoDB 사용

**Q2: 선수과목 검증은 어떻게 하나요?**
- A: Backend에서 Prerequisites 테이블 조회 후, 이수 완료 과목과 비교하여 검증

**Q3: 실제 학생 데이터는 어떻게 수집하나요?**
- A: CSV 임포트 기능으로 AIMS 성적표 업로드, 자동 파싱

**Q4: 배포 후 유지보수 계획은?**
- A: GitHub Actions CI/CD, AWS CloudWatch 모니터링, 정기적 백업

**Q5: 다른 학과에도 적용 가능한가요?**
- A: 네, CSV 데이터만 교체하면 다른 학과에도 적용 가능
