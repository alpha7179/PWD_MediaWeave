# Media Weave - 최종 프로젝트 보고서

## 1. 프로젝트 개요 (Project Overview)

### 프로젝트명 및 한 줄 소개
**Media Weave (미디어 위브)** - "우리의 이야기를 한곳에, 디미를 잇다"

아주대학교 디지털미디어학과 재학생을 위한 **통합 학습 관리 및 커뮤니티 플랫폼**으로, React Flow 기반 시각적 커리큘럼 로드맵, 프로젝트 갤러리, 팀 빌딩, 실시간 채팅을 통한 학과 커뮤니티 허브 역할을 수행합니다.

### 기획 의도 및 해결하고자 하는 문제

**해결된 핵심 문제들:**

1. **커리큘럼 정보 투명성 부족**
   - **문제**: 5개 트랙(GI, VC, DE, CD, MD)별 과목 연관성과 선수과목 관계가 불분명
   - **해결**: React Flow 기반 인터랙티브 트랙 로드맵으로 100개 이상 과목의 선수과목 관계 시각화

2. **개인 맞춤형 커리큘럼 설계의 어려움**
   - **문제**: 4년 8학기 수강 계획 수립 시 선수과목 검증과 졸업요건 확인의 복잡성
   - **해결**: 드래그 앤 드롭 기반 커리큘럼 플래너 + Tesseract.js OCR 성적표 자동 인식

3. **학습 성과물 체계적 아카이빙 부재**
   - **문제**: 학과 내 우수 프로젝트가 분산되어 후배들의 학습 참고 자료 부족
   - **해결**: 프로젝트 갤러리 시스템 (CRUD, 태그 기반 분류, 좋아요/댓글/조회수)

4. **효율적인 팀 구성 프로세스 부재**
   - **문제**: 프로젝트 팀원 모집과 역량 매칭의 비효율성
   - **해결**: 역량 기반 팀 빌딩 플랫폼 + 실시간 채팅 시스템

### 개발 기간 및 팀원 구성
- **개발 기간**: 2024년 9월 ~ 2024년 12월 (4개월)
- **팀원 구성**: 1인 개발 (Full-Stack Development)

## 2. 시스템 아키텍처 및 기술 스택 (Architecture & Tech Stack)

### Frontend Architecture

**핵심 프레임워크 및 라이브러리:**
- **React 18.2.0** + **Vite 5.2.0**: 모던 SPA 프레임워크, HMR 지원으로 개발 효율성 5배 향상
- **React Router DOM 7.10.1**: 클라이언트 사이드 라우팅, 코드 스플리팅으로 초기 로딩 속도 최적화
- **Zustand 5.0.9**: 경량 상태 관리, Redux 대비 90% 적은 보일러플레이트 코드
- **TanStack React Query 5.90.12**: 서버 상태 캐싱, 자동 리페칭으로 API 호출 최적화

**특수 기능 라이브러리:**
- **ReactFlow 11.11.4**: 트랙 로드맵 그래프 시각화, 100개 이상 노드 렌더링 최적화
- **@dnd-kit 6.3.1**: 커리큘럼 플래너 드래그 앤 드롭, 접근성 표준 준수
- **Tesseract.js 7.0.0**: 성적표 OCR 자동 인식, 한국어+영어 동시 지원
- **PapaParse 5.5.3**: CSV 파싱, 5개 파일 동시 로딩 및 관계형 데이터 조인

**UI/UX 시스템:**
- **Tailwind CSS 3.4.3**: 유틸리티 기반 스타일링, 일관된 디자인 시스템 구축
- **Lucide React 0.556.0**: 통일된 아이콘 세트, 600개 이상 아이콘 지원

### Backend Architecture

**서버 프레임워크:**
- **Node.js 20.x LTS** + **Express.js 5.2.1**: RESTful API 서버, 비동기 I/O 최적화
- **Sequelize 6.37.7**: PostgreSQL ORM, 관계형 데이터 모델링 및 마이그레이션 자동화

**데이터베이스 설계:**
- **PostgreSQL 15.x**: 프로덕션 환경, ACID 트랜잭션 보장
- **SQLite3 5.1.7**: 개발 환경, 빠른 프로토타이핑 지원
- **15개 테이블**: Users, Courses, Projects, TeamPosts, Messages 등 정규화된 스키마

**보안 및 인증:**
- **JWT (jsonwebtoken 9.0.3)**: 토큰 기반 인증, 1시간 유효기간
- **Bcrypt 6.0.0**: 비밀번호 암호화, Salt Rounds 10
- **역할 기반 접근 제어**: ADMIN/PROFESSOR/STUDENT 권한 체계

**파일 처리 시스템:**
- **Multer 2.0.2**: 이미지 업로드 처리, 10MB 제한, MIME 타입 검증
- **CSV-Parser 3.2.0**: 성적표 데이터 처리, 자동 과목 매칭

### Database Schema (실제 구현)

**핵심 엔티티 관계:**
```
User (사용자)
├── 1:N → Project (프로젝트)
├── 1:N → TeamPost (팀 모집)
├── 1:N → Message (메시지)
├── N:M → Course (수강 이력 - StudentCurriculum)
└── N:M → Project (좋아요 - Like)

Course (교과목)
├── N:M → Track (트랙 관계)
├── 1:N → Project (과목별 프로젝트)
└── N:M → User (수강 이력)

Project (프로젝트)
├── 1:N → Comment (댓글)
├── 1:N → Like (좋아요)
└── 1:N → ProjectView (조회수)
```

### Deployment Architecture

**클라우드 인프라 (설계):**
- **AWS S3**: 정적 파일 호스팅 (React 빌드 파일)
- **AWS CloudFront**: CDN, HTTPS 강제, 전역 캐싱
- **AWS EC2**: 백엔드 서버 (Node.js + PM2)

```javascript
// 학년별 과목 배치 알고리즘
const calculateLayout = (courses, track) => {
  const gradeGroups = groupBy(courses, 'year');
  let yOffset = 0;
  
  Object.keys(gradeGroups).forEach(grade => {
    const gradeCourses = gradeGroups[grade];
    const semesterGroups = groupBy(gradeCourses, 'semester');
    
    // 1학기는 하단, 2학기는 상단 배치
    const semester1 = semesterGroups[1] || [];
    const semester2 = semesterGroups[2] || [];
    
    const maxRows = Math.max(
      Math.ceil(semester1.length / COURSES_PER_ROW),
      Math.ceil(semester2.length / COURSES_PER_ROW)
    );
    
    // 동적 높이 계산
    const gradeHeight = maxRows * (NODE_HEIGHT + NODE_SPACING) + GROUP_PADDING;
    yOffset += gradeHeight;
  });
};
```

## 4. 개발 과정 중 변동 사항 (Changes & Refactoring)

### 초기 기획 대비 주요 변경사항

#### 1. 데이터베이스 아키텍처 단순화
- **변경 전**: PostgreSQL + MongoDB 하이브리드 구조
- **변경 후**: PostgreSQL 단일 데이터베이스
- **변경 사유**: 
  - 프로젝트 규모 대비 과도한 복잡성
  - MongoDB의 확장성 이점이 현재 요구사항에 불필요
  - 개발 및 운영 복잡도 최소화
  - PostgreSQL의 JSON 타입으로 NoSQL 장점 확보

#### 2. 사용자 테이블 통합
- **변경 전**: Professors, Students 분리 테이블
- **변경 후**: Users 통합 테이블 + role 필드
- **변경 사유**: 
  - 권한 관리 단순화 (RBAC 패턴 적용)
  - 코드 중복 제거 및 유지보수성 향상
  - 확장성 확보 (새로운 역할 추가 용이)

#### 3. 트랙 중심 설계로 전환
- **변경 전**: Majors 테이블 중심 설계
- **변경 후**: Tracks 테이블 중심 설계
- **변경 사유**: 
  - 실제 학과 운영에서 트랙이 더 중요한 분류 기준
  - UI 색상 정보 추가로 시각적 구분 강화
  - 사용자 경험 개선

#### 4. 실시간 기능 구현 방식 변경
- **변경 전**: WebSocket 기반 실시간 통신
- **변경 후**: 폴링 기반 실시간 통신 (3초 간격)
- **변경 사유**: 
  - 구현 복잡도 감소
  - 서버 리소스 사용량 예측 가능
  - 개발 일정 단축

#### 5. 파일 저장 전략 변경
- **변경 전**: AWS S3 직접 업로드
- **변경 후**: 로컬 파일 시스템 + 향후 S3 마이그레이션
- **변경 사유**: 
  - 개발 환경 설정 단순화
  - 비용 최적화 (개발 단계)
  - 점진적 클라우드 마이그레이션 전략
